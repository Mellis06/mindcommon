# Roadmap

The roadmap is provisional and should be revised through community and prospective-host co-design. Dates and deliverables are planning assumptions, not commitments by partner organisations.

## Stage 0 — Safe public foundation

- [x] Explain purpose, status, and prototype limitations.
- [x] Publish governance, architecture, and initial threat-model notes.
- [ ] Invite feedback from people with lived experience and relevant civil-society stakeholders.
- [ ] Identify independent privacy, security, legal, and ethics advisers.

## Stage 1 — Requirements and co-design

- [ ] Map stakeholders, power relationships, risks, and intended beneficiaries.
- [ ] Co-design consent language and governance procedures.
- [ ] Define access-request roles, appeal process, and community oversight.
- [ ] Agree measurable outcomes and safe evaluation methods.
- [ ] Confirm any host or community partnership in writing before describing it as established.

## Stage 2 — Synthetic-data backend

- [ ] Define API contracts and threat model.
- [ ] Implement identity and role model.
- [ ] Implement versioned consent records and withdrawal semantics.
- [ ] Implement access-request workflow with server-side policy checks.
- [ ] Implement restricted audit-event service and integrity strategy.
- [ ] Add automated tests, security checks, and OpenAPI documentation.
- [ ] Use synthetic data exclusively.

## Stage 3 — Independent review and controlled usability testing

- [ ] Accessibility and plain-language review.
- [ ] Security and privacy review.
- [ ] Community review of governance and benefit-sharing.
- [ ] Test only with synthetic or otherwise approved non-sensitive materials.
- [ ] Publish findings and limitations.

## Stage 4 — Any proposed field pilot

No field pilot is authorised by this roadmap. Proceed only after written host and community approval, applicable ethics review, data protection/legal review, safeguarding arrangements, independent security assessment, and a documented decision that the proposed design is appropriate.

## Measures to consider

- Participant comprehension of purposes and choices.
- Time and effort required to review or withdraw permissions.
- Percentage of access requests with documented purpose, scope, reviewer, and rationale.
- Time to resolve appeals or governance questions.
- Community assessment of representation, transparency, and perceived control.
- Number and severity of unresolved security/privacy issues.

Measures should be agreed with affected communities and must not create pressure to disclose sensitive information.
